# STM32 自平衡小车
基于STM32F103的自平衡机器人，从底层驱动测试逐步迭代至完整三环PID控制，并完成算法优化。
## 项目迭代目录
- **0 basic drive**：小车各模块驱动测试代码，主要用来测试电机驱动。小车运行时的抖动、倾倒会造成编码器连接不稳甚至断连，因此需要在底层驱动阶段反复验证。
- **1 pitch angle and complementary filtering**：俯仰角与互补滤波，完成MPU6050数据读取、换算。俯仰角是小车直立平衡的核心参数。MPU6050无法做到绝对水平安装，存在固定安装偏差，需要标定该偏差，在后续PID代码中减去。
> 互补滤波原理：加速度计ax/az可以给出绝对角度，但小车运动时精度差；陀螺仪角速度没有绝对基准，每次积分从零开始，但运动过程中数据稳定。最终融合角度以陀螺仪角度为主，叠加一小部分加速度计角度。
- **2 three-ring PID control**：小车完整控制工程。三环为角度环+速度环级联，外加转向环。仅角度环就可以实现直立和基础行进，但小车无法走直线，静止时也会缓慢漂移。增加速度环、转向环解决该问题。
- **3 program optimization**：PID算法优化，包括角度环微分先行、积分限幅抗积分饱和、输出偏移补偿。优化后小车原地制动更快，静态抖动更小。
## 开发遇到的问题与解决方案
### 1. MPU6050噪声问题
本项目对响应速度的优先级高于测量精度，因此在驱动中将MPU6050内置硬件滤波器关闭。蓝牙串口曲线出现更多尖峰，但噪声水平在控制回路可接受范围内。
### 2. PCB焊接与电源硬件故障
1. PCB焊接虚焊，导致MPU6050接触不稳定：读数会固定卡死在某个值，或者全部返回-1。通过重新焊接+机械加固，让MPU6050数据稳定，安装偏差固定。
2. 小车倾倒造成电源焊点松动，意外短路，保险丝发烫。断电排查后发现ST-Link和STM32芯片全部烧毁。更换保险丝、重焊电源接口，替换ST-Link与主控芯片，硬件恢复正常。
### 3. PID调参 & 编码器故障排查
- 仅角度环：KP/KI/KD调参相对简单，但给小车一个初速度之后，无法把速度归零。角度环只负责维持车身直立姿态，无法对平移速度做闭环控制。
- 增加速度环作为外环，和角度环串联构成串级双环PID：速度环P取2。P取3~4响应更快，但会带来来回震荡，故选择P=2。速度环I用于消除稳态漂移误差，Ki过大时微小摆动就会被放大，只能从小值逐步试参，最终Ki=0.05，小车行进时速度跟随效果良好。
- 增加转向环：开启转向环后，小车静止时会无故自旋。蓝牙串口打印编码器速度，发现单侧车轮编码器读数卡在0，差速突然变大引发自旋，但电机本身可以正常转动。
  使用基础驱动工程单独测试，确认编码器读取故障。重新焊接电机接口并加固硬件，修复编码器。
  转向环采用PI控制，最终参数Kp=3，Ki=2；参数继续增大，车身震动会变得剧烈。
- 增加保护：加入积分限幅与积分分离。防止小车碰撞、编码器接触不良时积分持续累积，同时抑制低速抖动。

硬件修复+参数整定完成后，小车可以稳定直行、转向。
